# Specification: 驗收標準與行為規則

## 1. 資料庫初始化規則
- 當伺服器啟動時，若 `price_records` 資料表不存在，應自動執行 `CREATE TABLE`。
- 建立資料表後，應自動 `INSERT` 至少兩筆預設的種子資料 (需確保同一種冰淇淋有跨越日期的兩筆價格記錄，用以測試趨勢功能，例如：過去與現在的麥當勞蛋捲冰淇淋)。

## 2. API 行為準則
### GET /api/records
- **行為**：回傳資料表內所有紀錄。不必在後端處理模糊搜尋，交由前端處理即時過濾。

### POST /api/insert
- 必須驗證 `date`、`item_name`、`price` 等欄位。
- 若新增成功，後端只能夠回傳純文字內容（如：`新增成功`），嚴禁回傳 JSON 格式。
- 若新增失敗，應回傳適當的 HTTP Status Code (500) 與純文字錯誤訊息。

## 3. 前端行為規則
### 畫面載入與趨勢渲染 (Initialization & Trend Arrow)
- 網頁開啟時，使用 Vanilla JS 呼叫 `GET /api/records`，取得所有資料。
- 取得資料後，前端必須**先依照日期 (date) 小到大（舊到新）對陣列進行排序**。
- **［趨勢箭頭觸發條件］**：在將資料繪製成表格時，須比對**同一商品 (item_name)**的前一筆歷史紀錄。若當前此筆價格大於前一筆的價格，則該列的「趨勢」欄位必須以醒目顏色 (例如 CSS `color: red`) 顯示向上的箭頭 `↑ 漲價`；若否則留空或顯示平穩。

### 即時查詢功能 (Real-time Search)
- 使用者在搜尋框**輸入字元的當下** (監聽 `input` 或 `keyup` 事件)，觸發前端 JavaScript 陣列過濾。
- 將包含輸入關鍵字的資料重新渲染至表格中，**不允許**發送新的網路請求 (`fetch`) 與**不允許**重新整理網頁。
- 若無符合資料，表格區塊應顯示「查無資料」或清空表格。

### 新增功能 (Insert)
- 使用者填寫完成後，點擊「新增」按鈕不可重整頁面 (`e.preventDefault()`)。
- 使用 `fetch` 將資料 `POST` 給 `/api/insert`。
- 收到後端傳回的文字訊息，透過 `alert(回傳文字)` 提示使用者。
- `alert` 關閉後，自動清空輸入表單，並重新呼叫一次 `GET /api/records` 覆蓋前端記憶體資料並重新渲染包含趨勢的表格。
